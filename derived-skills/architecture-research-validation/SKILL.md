# 架构调研验真

状态：知识转化草案，尚未安装或启用。

## 使用场景

设计新系统、评估架构建议或补齐类似系统调研。已有方案满足需求时复用，不无故添加缓存、消息队列、微服务或新数据库。

## 流程

1. 定义需求与边界。记录目标用户、功能、规模、延迟、成本和不做的部分；缺失数值标为待确认，不能编造。
2. 调研类似系统。优先已有资料和原始公开来源，记录日期、版本、事实、约束、取舍和与当前环境的差异。
3. 验证关键推荐。AI 输出先作为线索；来源无法确认时保留假设标签，必要时做有退出标准的小验证。
4. 顶层设计。只定义核心组件责任和必要交互，产出能说明关键流程的图与简短规格。
5. 用业务证据找主要矛盾。记录当前瓶颈、证据、方案、验收和回滚；解决后再评估下一项，必要时重做顶层设计。

## 输出

调研表：候选系统｜原始来源｜已核实事实｜适用条件｜环境差异｜可借鉴项｜待验证项。

规格：目标｜边界｜组件责任｜交互｜性能依据｜失败行为｜验收条件。

## 边界

案例中的技术栈不是默认答案；需求中的吞吐量不冒充已达到的性能。图画出来不等于方案正确。用户没有要求实施时，不修改生产代码或安装依赖。
