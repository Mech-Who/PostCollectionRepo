> **摘要：** Pi 通过极小系统提示词、四个核心工具和外置扩展保持上下文干净。它证明 Agent 框架的竞争力不只来自内置功能数量，也来自默认约束更少、可观察性更高和可替换边界更清楚。

## 我的理解
> 由 AI 根据原文整理，供审阅修改

Pi 的关键设计不是“功能少”，而是把产品能力和框架机制分开：框架保留稳定的最小循环，具体能力按需组装。这种设计降低默认上下文税，也让学习者能够看见模型收到的消息和工具调用。代价是用户需要自行承担扩展选型、隔离环境与组合验证，极简不等于零复杂度，只是把复杂度移到了明确的外部边界。

## 原文内容整理

Pi 由 libGDX 作者 Mario Zechner 开发，定位为终端编码 Agent 外壳。它不内置 MCP、子 Agent、计划模式、权限弹窗、后台 Bash 或待办系统，而是提供扩展、技能、模板和主题机制。系统提示词静态部分约 90 个英文单词，运行时加上工具定义和上下文文件后约 200 至 400 词。

核心工具只有 `read`、`write`、`edit`、`bash`，另有 `grep`、`find`、`ls` 等辅助能力；支持 30 多家模型供应商并允许会话中途切换模型。它公开完整提示词和工具输入输出，并以树状会话保留不同尝试分支。

官网的“What we didn't build”解释了主动舍弃：MCP 可能在会话开始注入大量工具描述；子 Agent 会增加复杂度并降低可观察性；反复权限弹窗可能导致确认疲劳，安全边界更适合交给容器隔离。文章认为，Pi 代码量小而又能在 Agent 基准中取得较好成绩，因而适合用于学习 Agent 的最小必要结构。
