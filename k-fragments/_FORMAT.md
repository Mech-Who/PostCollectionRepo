# K-Fragment ABCD 模板

K-Fragment 用于把文章中的可复用知识压缩为可检索、可执行、可追溯的独立片段。每个片段只表达一个核心主题；无法从原文确认的内容应明确标注“待验证”，不要补造。

```markdown
---
title: "主题名称"
date: YYYY-MM-DD
category: "分类"
depth: "深度|标准"
layer: layer2
tags: [关键词1, 关键词2, 关键词3]
source_article: "对应文章文件名（不含扩展名）"
source_url: "原文链接"
---

# K-Fragment: 主题名称

## A. Applicable — 适用场景

- 这条知识解决什么问题
- 在什么前提、角色或系统中使用
- 哪些可观察信号说明应该调用它

## B. Boundary — 边界与注意事项

- 不适用的情况与反例
- 必要前置条件、风险和副作用
- 容易误用的概念边界

## C. Core — 核心要点

1. 可复述的核心原理
2. 可直接执行的方法或步骤
3. 关键因果关系与决策依据

## D. Data — 关键数据与决策记录

- 原文中的数字、版本、阈值、对比结果或引用
- 保留数据口径、时间范围和来源上下文
- 没有关键数据时写“原文未提供可验证数据”
```

## 质量要求

- **原子性**：一份文件只承载一个可独立检索的主题。
- **可执行**：A 和 C 能帮助读者判断“何时用、怎么做”。
- **有边界**：B 必须写明限制，不能只复述优点。
- **可追溯**：D 保留关键证据，frontmatter 指向来源文章和原文链接。
- **少而精**：删除宣传语、重复表述和脱离上下文后无意义的信息。
