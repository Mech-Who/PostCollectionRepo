# K-Fragment: 规则驱动的组合涌现玩法

## A. Applicable — 适用场景

- 设计开放世界、沙盒、解谜或沉浸模拟游戏，希望少量机制产生大量解法时。
- 玩家需要用常识推理，而不是记忆每个谜题的专属脚本时。
- 探索、战斗和多人协作希望复用同一组能力与环境规则时。

## B. Boundary — 边界与注意事项

- 不适合依赖严格演出节奏、唯一答案或强可控竞技平衡的核心场景。
- 通用规则会带来组合爆炸，必须提前设计规则优先级、性能预算、异常检测和调试工具。
- 多人环境需要处理确定性、状态同步、延迟补偿和极端并发交互。

## C. Core — 核心要点

1. 先定义能改变空间、时间、连接或材质状态的少量基础动词。
2. 让能力、物体和环境共享统一规则，而不是为每种组合编写一次性脚本。
3. 同一能力应自然跨越探索、解谜、战斗与协作，降低学习成本。
4. 目标只定义约束，不预设唯一过程，让玩家组合规则产生答案。
5. 用自动化组合测试、状态追踪和可视化调试控制涌现系统的工程风险。

## D. Data — 关键数据与决策记录

- 原文展示三种能力：立石、定影、浮金。
- 典型规则链：草地燃烧 → 空气受热 → 形成上升气流 → 滑翔起飞 → 下落攻击。
- 原文为首曝 PV 观察，尚无性能、联机规模和正式玩法覆盖率数据。
