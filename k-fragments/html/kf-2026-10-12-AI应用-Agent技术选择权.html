Agent 技术选择权

A — Applicable

团队将实现工作交给 Coding Agent，需控制框架与依赖增长、外部数据流向或长期维护成本时。

B — Boundary

规则按任务风险制定，不把所有小选择变成审批。本文为访谈翻译整理，未核对原始录音；组织效率改善是待测量结果。禁止技术栈需与仓库实际状态一致，不能用过时规则误阻正常交付。

C — Core

  1. 需求空白会成为 Agent 的默认技术选择；验收功能之前先使这些决定可见。
  2. 写清现有技术栈、允许依赖、外部服务、版本和数据流范围。
  3. 重要限制由现有依赖检查、静态分析或 CI 验证；自然语言提醒不能代替证据。
  4. 保留选型原因和恢复入口，验收新依赖与外部资源的来源。
  5. 生成速度与交付吞吐量分别计量；优化当前等待、审查或发布瓶颈。
